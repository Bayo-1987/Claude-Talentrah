### What changed
Multi-line fields were inconsistent: raw `<textarea>`s hand-styled to look like one-line inputs, some long text in one-line inputs, no shared component. This PR is the component and the rules around it; the remaining call sites follow in PR 1b.
- `src/components/ui/text-area.tsx`: the shared `<TextArea>`: label, help and error wired with aria-describedby, 4+ rows, a visible resize handle, optional auto-grow, and a character counter. The frame is shared with the bold/italic editor (`src/components/ui/writing-box.ts`, used by `MinimalRichEditor`). Every other attribute passes through, so a conversion changes no id, name or payload.
- `src/lib/text-limits.ts`: the approved caps (app-level only, no database constraint) and one counting rule, `countForLimit` / `fitsLimit`, imported by the box AND by the server checks: trimmed UTF-16 length, a CRLF line break counts as one, a value already over its cap can be saved unchanged or shortened, never made longer. Tested on emoji, flags, ZWJ sequences, CJK, Arabic, Hebrew and combining marks.
- `src/lib/text-counter.ts`: the counter is announced politely and only when it crosses 80%, 90%, the limit, or goes over; a paste that does not fit is refused whole with a visible message (never cut to fit).
- For a global audience: `dir="auto"`; 16px text on a phone (15px from `sm`) so iOS does not zoom on focus; nothing is rewritten or truncated while an input method is composing.
- Call sites in this PR: the public contact form (5000, and the server had no cap before) and the feedback form (5000, the server's cap now counted with the same function).
- `tests/ui/no-raw-textarea.test.ts`: a raw `<textarea>` outside the component fails CI. Its PENDING list holds every file still to convert (PR 1b) and the two scholarship fields that belong to their owner; it only shrinks.
