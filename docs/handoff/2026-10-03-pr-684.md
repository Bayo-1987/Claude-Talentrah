### What changed
- **Country list.** Signup and Settings went from eight hard-coded names to every ISO 3166-1 country plus Kosovo, taken from the one list in `src/lib/jobs/countries.ts` (`COUNTRY_DISPLAY_NAMES`), so the app has one country list. Order: Nigeria, United Kingdom, United States, Canada, then everything else A–Z, then "Other". Every value the old list accepted is still on it, spelled the same, so no stored `profiles.country` stops validating.
- **A–Z order is a plain comparison on an accent-folded key** (`compareCountryNames`: `normalize("NFD")`, strip combining marks `\p{M}`, lowercase), not `Intl.Collator` or `localeCompare`, which follow the ICU data of whichever Node or browser runs them (a server/client `<select>` order mismatch is a hydration error). Pinned by test: the first five entries and the neighbours of Åland Islands, Côte d'Ivoire, Curaçao, Réunion and Türkiye. The names are committed (`ISO_ENTRIES`), not computed with `Intl.DisplayNames`; a test asserts none of the three list files uses `Intl.DisplayNames`, `Intl.Collator` or `localeCompare`.
- **Autocomplete and password minimum.** The country select carries `autocomplete="country-name"`. The signup and reset-password inputs carry `minLength` from `PASSWORD_MIN_LENGTH`, the constant the server rule and the requirements list already read, so the three cannot drift. The login form and the admin sign-in have no `minLength` (pinned), so a user with an older, shorter password can still sign in; a source scan fails if any file with a `current-password` input mentions `minLength`.
- **Georgia and Jersey.** `countryCodeForLabel` maps an exact dropdown label straight to its code (Georgia → GE, Jersey → JE). The free-text resolver for job locations is unchanged and still refuses a bare "Georgia"/"Jersey" (pinned).
- **Employer salary-currency default (one-line rule).** The seven mapped countries and the EU members keep their currency; every other listed country, and "Other", now defaults to **USD**; an unset, blank or unrecognised country stays NGN. This is a form default only (it preselects the posting form's currency select) and is stored on no profile; production has 16 profiles (7 Nigeria, 9 with no country), so no existing profile changes. **EU → EUR is not new in this PR**: it came in with EMP-1 (`e547f58`).
- **What profiles.country does for a new country** (billing region, feed default, salary currency) is pinned for every entry in the list in `tests/auth/signup-countries.test.tsx`: only Nigeria is "Nigeria" for billing (everyone else, and any unknown value, is "Outside Nigeria — billed in naira (₦) by card"), only the four tracked countries default the feed, and a new country cannot land in a wrong region.
- **Database.** Read-only inspection of production found no CHECK constraint on `profiles.country` (plain nullable `text`), no RLS policy that reads it, and a `handle_new_user` trigger that copies `raw_user_meta_data ->> 'country'` verbatim. No migration. `tests/auth/signup-country-profile.test.ts` (CI only, `@talentrah.test` addresses, deletes only the users it created, refuses any non-CI database through `tests/setup.ts`) proves signup stores the exact value for Japan, Côte d'Ivoire, Åland Islands, Curaçao, Réunion, Türkiye, Georgia, Jersey and Other, and that an owner can save three of them on their own profile.

### Tests changed (each a deliberate rule change, none loosened)
- `tests/employer/salary-currency.test.ts`: `Other`, `Japan`, `JP`, `Australia` expected NGN, now expect USD (new rule); the unset/unrecognised cases are kept as NGN.
- `e2e/post-job-form-layout.spec.ts`: `Other` expected NGN, now USD (same rule).
- `e2e/signup-form-reset.spec.ts`: the password it fills went from `weak` to `weakpassword`. The browser's own `minLength` now stops `weak` before the action runs, which would never exercise the failed-submission re-render the test is about. The assertion is unchanged ("Password doesn't meet the requirements below"); a unit test pins that `weakpassword` clears the browser minimum and still fails the server rule.
