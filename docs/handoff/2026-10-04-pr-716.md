### What changed
Adds `POST /api/admin/rescore-stale-match-scores` (admin header or the `CRON_SECRET` bearer; constant-time check; bare 401 with no detail): a **dry run by default** that reports the SHAPE of the change (up/down/same, size buckets, label changes as the feed shows them, rows ending with no tier, rows per user ranked, ten largest drops as numbers), and with `{"write": true}` a rescore of exactly the `match_scores` rows with no `explanation.roleFit`, for users with a base resume. Bounded (default 1,000 rows per call, whole users only, a user above the limit is processed whole, a 200 s self-stop under `maxDuration = 300`) and resumable (`nextCursor`). Skips and counts: users with no base resume, closed/superseded/gone postings, and postings still carrying the stub enrichment skill. Writes only `match_scores`. A `verify` mode recomputes a random sample and compares. New manual workflow `.github/workflows/rescore-stale-match-scores.yml` (`workflow_dispatch`, `dry_run` defaults to true, a write run also needs `confirm_write` = `write`, `CRON_SECRET`, no new secret; **needs S2's review, and it only becomes runnable once merged**). The dry run is a bounded chain reconciled against an independent single-query count (`{count:true}`); the owner approves a write run only if the two numbers match. A DB-backed cursor test (`rescore-stale-cursor.test.ts`) runs in CI only. **Merging does not rescore anything.** No migration.
