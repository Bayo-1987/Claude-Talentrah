### What it changes
Nine foreign keys into `profiles` go from `ON DELETE CASCADE` to `ON DELETE SET NULL` and their columns become nullable: `payment_transactions.user_id`, `credit_ledger.user_id`, `user_passes.user_id`, `referral_reward_events` (both sides), `referrals` (both sides), `mentorship_sessions.mentee_id`, `mentorship_reviews.reviewer_id`. `payment_status` gains `needs_refund`; the existing notes-ownership trigger function nulls `mentee_notes` in the same UPDATE that detaches a mentee; `account_deletion_fk_catalog()` (service role only) lets tests read FK rules. In code: `fulfillPayment` records a verified payment for a deleted user as `needs_refund` (alert once, grant nothing, webhook 200); renewals skip an ownerless Pass; mentorship lists show "Deleted user"; the referral reward job skips a deleted referrer. Full reasoning and the three rolled-back evidence runs are in the PR body.
