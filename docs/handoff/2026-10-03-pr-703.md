### What changed
A scholarship listing went public with a reviewer's remark as its deadline, because `deadline_note` is valid only alongside a verified-deadline stamp and nothing enforced it. Three layers: a data fix for the one listing (applied 2026-10-03 17:23:48 UTC); `publicDeadlineNote()`, one fail-closed function every public surface asks (card, list row, detail page and its meta description, blog fact card, landing pages), with a ratchet that fails the build on any other read of the column; and migration 0217, two CHECK constraints (a verified listing may carry a note only with a stamp; a note is at most 600 characters). The admin form shows a live count against 600 and turns either refusal into a sentence.
Consequences worth knowing: a listing added by hand with a deadline note cannot be approved (the manual form never sets a stamp), by design; and 600 is tight, because the longest real note in production is 590 (`tests/scholarships/seed-note-limits.test.ts` keeps the source config under it, since one over-length note fails the whole nightly batch it is in).
Left alone: reviewer commentary in three eligibility columns on the same listing (owner's decision, see Follow-ups).
