### What changed
Test fixtures keep tripping the Secret scan for innocent reasons: a sentinel named `SECRET_JD` (#667: three heads red before anyone read why), an HMAC literal (#671). CI scans **commits**, so renaming in a later commit does not clear a finding in an earlier one, and after the push the only cure is an allowlist entry.
- `tests/ci/no-credential-shaped-identifiers.test.ts` fails, with `file:line:name`, on any line in `tests/` or `e2e/` that this repo's `talentrah-hardcoded-credential` rule would trip, **while the fix is still a rename**.
- `tests/support/credential-shaped-scan.ts` reads the rule, its `keywords` and the allowlist **from `.gitleaks.toml` itself** (a small extractor; no TOML library exists and this is not worth a dependency), so it cannot drift from CI. It reproduces the regex per line, the allowlist (values against the captured secret, paths against the file path), and the **keyword prefilter per file** exactly as gitleaks applies it per fragment.
- Its known-bad/good lines live in `tests/support/credential-shaped-fixtures.txt`, whose **exact path** is allowlisted in `.gitleaks.toml` (reason there): no `.ts` file contains credential-shaped lines.
- **What it does not cover, said in the test's header:** git history; and gitleaks' **default rules** (`useDefault = true` pulls in `generic-api-key`, an entropy rule). An approximation of the latter was calibrated against today's tree and reported 49 false positives, so it was deliberately not shipped.

**Hardening after review (second commit).** (1) The extractor now fails loudly: no rule, an empty regex, an empty keyword list, an empty allowlist `regexes`/`paths`, or a missing `[allowlist]` section each throw an Error naming what is missing, so a changed `.gitleaks.toml` cannot make the scan pass by finding nothing; eight reshaped copies of the real file are tested (five were red before the change), and a legal reshape (keywords on one line) must parse correctly. (2) The fixtures allowlist entry is pinned to be exactly one anchored path with no wildcard, matching nothing nearby, and every quoted value in the fixtures file must contain `FAKE` (the already-allowlisted ALLOW sentinels excepted, which must be suppressed by a real entry); a real-looking line added to it fails the test (shown red).

**What CI's real scan taught this PR (four findings on the first version).** (1) The keyword prefilter is per *file*, not per line: `const PASSED = "…"` (a name containing `pass`, in a file that mentions "secret" anywhere) is a finding; my first emulation filtered per line and missed it. (2) The default `generic-api-key` rule matched fixture lines of the shape `NAME", "value"` (its separator class includes a comma). (3) Both came from fixtures spelled inline in a `.ts` file. (4) The scan reads commits, so the fix could not be a follow-up commit: the branch was squashed to one clean commit and updated with `--force-with-lease` (own unmerged branch; the content was made-up fixtures, not a credential).
