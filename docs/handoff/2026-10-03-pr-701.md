### What changed
Several sessions tripped the credential-shaped check (#680) with fixture literals and had to add exact-value allowlist entries. This makes the right way the easy way.
- `tests/support/fake-secret.ts`: `fakeSecret(kind)` for `paystackSecret`, `resendKey`, `stripeShaped`, `token` and `password`. Each value is assembled at run time from parts (the prefixes are joined, the random part comes from `node:crypto`), so no credential-shaped literal ever appears in source. The type is named `FakeKind`: a name containing "secret" assigned a quoted literal is exactly what the scan flags, and the helper's own source is scanned too.
- `tests/support/fake-secret.test.ts`: each kind matches the shape its consumer expects (Paystack `sk_test_` + 40 hex, Resend `re_` + 8 + `_` + 24, Stripe-shaped `sk_test_` + 24 base62, a 32-hex token, and a password sample that passes the app's own `isPasswordValid`), every call is fresh, the helper's source and a consumer of it pass the #680 scan, and the same values written as literals would be flagged (so the helper is what keeps them out).
- The runtime-built fixtures that were trivial to move now use it: the `E2E-<uuid>Aa1!`-style passwords in 8 e2e specs and 4 unit tests, and the cron value in `tests/api/purge-demo-attempts-route.test.ts`. The historic allowlist entries stay (they cover old commits).
