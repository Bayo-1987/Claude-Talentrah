### What changed
`anonymous_demo_attempts` (migration 0208, #667) holds no personal data, but an attempt log should not grow forever. This adds a **daily purge of rows older than 90 days**, with **no migration** (no SQL function):
- `src/lib/demo/attempt-retention.ts`: selects the ids of the oldest expired rows, **1,000 per batch, 10 rounds per run** (at most 10,000 rows a run), and deletes them **by id with the age predicate re-asserted inside every delete**, using the service-role client. A run that uses all its rounds with a full last batch reports `hitCap`, and the next daily run continues. A failed query is returned as an `error` (the route answers 500), never swallowed.
- `/api/admin/purge-demo-attempts`: **its own route and its own cron entry** (`0 19 * * *`, the 18th cron), not a step inside `delete-stale-postings`, so a failure in one purge never stops another sweep and each has its own log line (`[demo-attempt-purge] cron run: cutoff=… deleted=… rounds=… hitCap=…`). GET is the Vercel cron (`Authorization: Bearer <CRON_SECRET>`), POST is the manual path (`x-admin-secret`); both fail closed.
- Tests, written first (26 failed against stubs, then green): a row at 91 days is deleted and one at 89 days is kept; the cutoff is strict; delete is by id with the predicate re-asserted; the batch cap holds (exactly 20 of 25 with batch 10 and 2 rounds, and the next run finishes); the route refuses a request with no credential, a wrong or mis-schemed bearer, the admin secret on the cron path, the cron bearer on the manual path, and every request when `CRON_SECRET` is unset; plus a DB-backed twin against the real table (runs in CI). `tests/api/contract.test.ts` §0 also discovers the route from disk and asserts it answers 401 with no credential.
- Left alone: `delete-stale-postings`, and `anonymous_demo_runs` (its rows are lifetime-limit keys by design, a separate retention question).
