### What it changes
`tests/support/global-teardown.ts` (a Vitest `globalSetup`, so outside every test file and outside `tests/setup.ts`'s guard) swept `@talentrah.test` accounts older than two hours and fixture organisations on whatever database `.env.local` named. On 2026-10-02 a DB-backed file run with `ALLOW_TESTS_AGAINST_HOSTED=yes-i-mean-it` against `talentrah-preview` ended with the sweep deleting stale accounts there (563 `user_deleted` events in the project's auth audit log between 17:52:28Z and 17:54:40Z, every one `@talentrah.test`, none of any other domain; `test_user_pool` 41 rows intact, `ci_test_locks` empty). It now deletes only on a local stack with a key that does not belong to production; anywhere else it refuses loudly and deletes nothing. The opt-in is its own variable (`ALLOW_GLOBAL_SWEEP_ON_NON_LOCAL=yes-i-mean-it`), the suite's hosted opt-in does not open it, and production cannot be opened by it at all.

### Tests first
`tests/support/global-teardown-guard.test.ts`, 11 tests against a fake client that records every call: 8 failed against the unguarded teardown, all 11 pass with the guard. No database is needed.

### Rule from the owner, same day
Database-backed suites run in CI only; they are not run against `talentrah-preview`, even with the escape hatch. Evidence before CI comes from a rolled-back transaction.
