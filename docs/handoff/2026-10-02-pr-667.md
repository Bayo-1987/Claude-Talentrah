### What changed
Production had 3 demo runs in its history, every one with a null `ip_hash`, and a refused or failed attempt left no trace, so "barely used" and "silently failing" were indistinguishable. This PR adds the measurement and makes the page honest; **it changes no limit**.
- **Attempt log**: migration 0208, table `anonymous_demo_attempts` (outcome `success|refused|error|invalid`, `reason`, `error_class`, `ip_rule_active`) and a read-only view `anonymous_demo_outcomes_7d`. No PII, and **guaranteed by the schema**: `reason ~ '^[a-z_]{1,32}$'` and `error_class ~ '^[A-Za-z0-9_.]{1,64}$'` check constraints. The route writes one row per POST, fail-safe (a log failure never changes the answer).
- **A value that does not fit is never repaired**: an unknown `reason` is written as `other`, a malformed `error_class` as `Other`; the raw value goes to the server log once, never to the database. `src/lib/demo/attempt-codes.ts` lists every code the route writes.
- **Copy**: the caption is "Try it free — no account needed. One free preview per visitor."; the hero lede makes no claim of its own; the auth side-panel says "job description", not "job link".
- **Refusals**: all four reasons render a clear reason and a "Create a free account" link; our own failures never say the visitor "used" anything.
- **`ANON_DEMO_IP_SALT` stays unset** (shared mobile-carrier addresses); a test pins that no IP rule applies without it.
- Left alone on purpose: the homepage still says "companies hiring across Nigeria and Africa" (to change with the move to a global audience), and `how-it-works-section.tsx` step 1 still says "Paste a job link or description".

### Secret scan: a false positive on all three runs, found late
The `Secret scan` check failed on every run of this PR (`c48a9e9`, `f36e81a`, `f70d52f`). The finding (rule `talentrah-hardcoded-credential`, `tests/demo/jd-demo-route-attempts.test.ts:38`, first carried by commit `a6609fc`) is `const SECRET_JD = "CONFIDENTIAL-PASTE-9f3a ".repeat(6);`: a sentinel the test pastes as a visitor's job description to prove pasted text never reaches the attempt log. It is not a credential (nothing to rotate). It matched only because the constant's name contains "secret". **I did not read this PR's CI before telling the merge captain it could merge on green; that was my miss.** Fix: the constant is renamed (`PASTED_JD_SENTINEL`), and because the first commit carrying it is already in the PR's history, the exact value `CONFIDENTIAL-PASTE-9f3a` is allowlisted in `.gitleaks.toml` with the reason written down, as that file requires. gitleaks is not installed on this machine, so the fix was checked by emulating the rule's regex (the old line matches, its secret group is matched by the allowlist regex, the renamed line does not match, and no other line in this PR's changed files matches); CI is the real check.

### What changed since the first push (code only; the migration did not change after `f36e81a`)
- An unknown value is **never repaired to fit**: an unknown `reason` is written as `other` (now a listed code), a malformed `error_class` as `Other`; no stripping, no truncating (turning `ünï` into `n` would write a valid-looking code that means something else). The raw value goes to the **server log once** (bounded, per process), never to the database.
- Tests: unknown reason → `other`; malformed error class → `Other`; a known code passes through unchanged; the stripping path no longer exists (re-adding it fails 5 tests); the raw value is in the log and not in the row; the migration's header comment and `attempt-codes.ts` cannot drift; the 7-day view reports only codes `attempt-codes.ts` lists (DB-backed, runs in CI).
- Nothing reads the old hyphenated reason markers (`test-<uuid>`, `dryrun-marker`): they existed only in an earlier version of this PR's own test and in the first dry-run script; the only reader or writer of the table and the view in the repo is `src/lib/demo/attempt-log.ts` (no admin page, no other fixture).
